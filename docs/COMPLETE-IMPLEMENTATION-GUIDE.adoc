## 1. Theoretical Foundations

### Core Papers & Concepts

#### Type Theory
- **Hindley-Milner Type Inference**
  - Principal type inference algorithm
  - Unification algorithm
  - Type substitution and instantiation
  - Reference: "A Theory of Type Polymorphism in Programming" (Milner, 1978)

- **Polymorphic Type System**
  - Type variables (α, β, γ)
  - Type schemes (∀α. τ)
  - Generalization and instantiation
  - Reference: "Principal type-schemes for functional programs" (Damas & Milner, 1982)

#### Pattern Matching
- **Pattern Compilation**
  - Exhaustiveness checking
  - Redundancy detection
  - Decision tree compilation
  - Reference: "The Implementation of Functional Programming Languages" (Peyton Jones, 1987)

#### Capability-Based Security
- **Object-Capability Model**
  - Capabilities as unforgeable references
  - Principle of least authority
  - Reference: "Capability-Based Computer Systems" (Levy, 1984)

- **Consent-Driven Computing**
  - Explicit permission grants
  - Temporal capabilities
  - Audit logging
  - Philosophy: User agency over computation

#### Dimensional Analysis
- **Units of Measure**
  - Type-level dimensional analysis
  - Unit checking at compile-time
  - Reference: F# units of measure implementation

#### Concurrency
- **Actor Model** (for workers)
  - Message passing
  - Isolated state
  - Reference: "A Universal Modular Actor Formalism" (Hewitt et al., 1973)

## 2. Language Specification (EBNF)

### Complete Grammar

```ebnf
(* WokeLang EBNF Grammar *)

program = { top_level_item } ;

top_level_item = function_def
               | consent_block
               | gratitude_decl
               | worker_def
               | side_quest_def
               | superpower_decl
               | module_import
               | pragma
               | type_def
               | const_def
               ;

(* Functions *)
function_def = [emote_tag] "to" identifier "(" [param_list] ")" ["->" type]
               "{" [hello_msg] { statement } [goodbye_msg] "}" ;

param_list = param { "," param } ;
param = identifier [":" type] ;
hello_msg = "hello" string_literal ;
goodbye_msg = "goodbye" string_literal ;

(* Types *)
type_def = "type" identifier [type_params] "=" type_body ;
type_body = struct_def | enum_def | type_alias ;
struct_def = "{" field_list "}" ;
field_list = field { "," field } ;
field = identifier ":" type ;
enum_def = enum_variant { "|" enum_variant } ;
enum_variant = identifier ["(" type { "," type } ")"] ;
type_alias = type ;

type = "Int" | "Float" | "String" | "Bool" | "Unit"
     | "[" type "]"                    (* Array *)
     | type "->" type                  (* Function *)
     | "Result" type type              (* Result *)
     | "{" field_list "}"              (* Record *)
     | identifier [type_args]          (* Named type *)
     | type "@" unit                   (* Quantity with unit *)
     ;

(* Constants *)
const_def = "const" identifier [":" type] "=" expression ";" ;

(* Statements *)
statement = var_decl
          | assignment
          | return_stmt
          | conditional
          | loop
          | attempt_block
          | consent_block
          | expression_stmt
          | worker_spawn
          | complain_stmt
          | emote_annotated_stmt
          | decide_stmt
          ;

var_decl = "remember" identifier [":" type] "=" expression ";" ;
assignment = identifier "=" expression ";" ;
return_stmt = "give" "back" expression ";" ;

conditional = "when" expression "{" { statement } "}"
              ["otherwise" "{" { statement } "}"] ;

loop = "repeat" expression "times" "{" { statement } "}" ;

attempt_block = "attempt" "safely" "{" { statement } "}"
                "or" "reassure" string_literal ";" ;

consent_block = "only" "if" "okay" string_literal
                "{" { statement } "}" ;

worker_spawn = "spawn" "worker" identifier ";" ;

complain_stmt = "complain" string_literal ";" ;

decide_stmt = "decide" "based" "on" expression "{"
              { match_arm } "}" ;

match_arm = pattern "->" "{" { statement } "}" ;

pattern = literal
        | identifier
        | "_"
        | identifier "(" [pattern { "," pattern }] ")"
        ;

(* Expressions *)
expression = literal
           | identifier
           | binary_expr
           | unary_expr
           | call_expr
           | lambda_expr
           | array_literal
           | record_literal
           | index_expr
           | field_access
           | "(" expression ")"
           ;

binary_expr = expression binary_op expression ;
binary_op = "+" | "-" | "*" | "/" | "%" | "==" | "!=" | "<" | ">" | "<=" | ">=" | "&&" | "||" ;

unary_expr = unary_op expression ;
unary_op = "-" | "!" ;

call_expr = identifier "(" [arg_list] ")" ;
arg_list = expression { "," expression } ;

lambda_expr = "with" "(" [param_list] ")" "->" expression ;

array_literal = "[" [expression { "," expression }] "]" ;

record_literal = identifier "{" [field_init { "," field_init }] "}" ;
field_init = identifier ":" expression ;

index_expr = expression "[" expression "]" ;
field_access = expression "." identifier ;

(* Modules *)
module_import = "use" qualified_name ["renamed" identifier] ";" ;
qualified_name = identifier { "." identifier } ;

(* Workers *)
worker_def = "worker" identifier "{" { statement } "}" ;

(* Side Quests & Superpowers *)
side_quest_def = "side" "quest" identifier "{" { statement } "}" ;
superpower_decl = "superpower" identifier "{" { statement } "}" ;

(* Gratitude *)
gratitude_decl = "thanks" "to" string_literal ";" ;

(* Pragmas *)
pragma = "#" pragma_directive ("on" | "or") ";" ;
pragma_directive = "care" | "strict" | "verbose" ;

(* Emotes *)
emote_tag = "@" identifier ["(" emote_params ")"] ;
emote_params = identifier "=" literal { "," identifier "=" literal } ;

(* Literals *)
literal = integer | float | string_literal | boolean | unit ;
integer = digit { digit } ;
float = digit { digit } "." digit { digit } ;
string_literal = '"' { character } '"' ;
boolean = "true" | "false" ;
unit = "()" ;

identifier = letter { letter | digit | "_" } ;
```

## 5. Seam Analysis Points

### What is a "Seam"?

A seam is a boundary between components where integration happens. Seam analysis ensures components work together smoothly.

### Complete Seam List

#### Horizontal Seams (Pipeline Stages)

1. **Source → Lexer**
   - ✓ Valid source code tokenized correctly
   - ✓ Invalid characters reported
   - ✓ Position tracking for errors

2. **Lexer → Parser**
   - ✓ All tokens recognized
   - ✓ Span information preserved
   - ✓ Error recovery works

3. **Parser → Type Checker**
   - ✓ All AST nodes typed
   - ✓ Type errors have spans
   - ✓ Polymorphic types work

4. **Type Checker → Interpreter**
   - ✓ No runtime type errors for well-typed programs
   - ✓ Function calls safe (arity, types)

5. **Interpreter → Output**
   - ✓ Values formatted correctly
   - ✓ Side effects execute in order
   - ✓ Exit codes meaningful

#### Vertical Seams (Cross-Cutting Concerns)

6. **Interpreter ↔ Security**
   - ✓ Consent blocks check permissions
   - ✓ Pragmas control behavior
   - ✓ Audit log complete

7. **Interpreter ↔ Stdlib**
   - ✓ All functions callable
   - ✓ Errors propagate correctly
   - ✓ Capabilities passed through

8. **Interpreter ↔ Workers**
   - ✓ Workers spawn successfully
   - ✓ Errors isolated per-worker
   - ⚠️ Message passing TBD

9. **Type Checker ↔ Stdlib**
   - ✓ All stdlib functions have types
   - ✓ Types match implementations

10. **Parser ↔ Module System**
    - ✓ Imports parsed correctly
    - ✓ Circular deps detected
    - ✓ Renamed imports work

#### Feature Seams

11. **Pattern Matching**
    - ✓ Parser → patterns in AST
    - ✓ Type Checker → pattern types
    - ✓ Interpreter → pattern execution

12. **Consent System**
    - ✓ Parser → consent blocks
    - ✓ Interpreter → permission checks
    - ✓ Security → audit log

13. **Workers**
    - ✓ Parser → worker defs
    - ✓ Interpreter → spawn workers
    - ⚠️ Worker → Main communication TBD

### Seam Analysis Protocol

For each phase, perform:

1. **Smoothing** - Make interfaces work together
   - Consistent error handling
   - Uniform data flow
   - No impedance mismatches

2. **Sealing** - Prevent leaks and errors
   - No panics
   - No memory leaks
   - No undefined behavior
   - Proper resource cleanup

3. **Shining** - Polish and optimize
   - Clean code
   - Documentation
   - Performance optimization
   - User-friendly output
